# Temporary light profiles and presence holds

Daytime and nighttime `service_data_on` brightness and Kelvin values are temporary controller settings. Entity Controller captures readable original brightness and color values before its first light call in a session. Switching between timer and stay mode retains that original snapshot.

Before a session exits through a transition or its day/night window changes, the manager restores fields that still match the values it applied. Restoration runs before an automatic `turn_off`. Manual takeover also releases these settings, including in stay mode or with blocking disabled. A manually changed brightness or color is preserved; unchanged controller-owned fields can still be restored. Changing from a color mode such as RGB to Kelvin restores the original color representation when available.

Home Assistant's generic light attribute service is `light.turn_on`. There is no universal service to write retained brightness or color while a light is off without turning it on. Entity Controller therefore never sends `turn_on` merely to restore an off, unavailable or missing light. It retains an in-memory pending snapshot while the controller remains loaded and checks the next observed ON event. Only values still matching the controller's values are restored; explicit manual ON brightness or color values are preserved. An OFF light remains OFF.

Side-effect-free reconciliation (including enable/disable reconciliation and hot reconfiguration) discards ownership without sending restoration services. Snapshots and pending restoration are not persisted. On controller removal or unload, unchanged readable attributes may first be restored on an ON light; pending OFF-light snapshots are then discarded. Restart cannot recover discarded in-memory snapshots. Devices that omit their original attributes cannot have those attributes restored. Values reported differently from the requested values (for example clamped Kelvin or device rounding) are conservatively treated as no longer owned and left unchanged. These limits avoid overwriting user settings or switching on an off light.

Light-specific service fields are routed only to `light` outputs. Mixed `switch` and `fan` outputs still receive their own turn services without brightness, color or light transition fields. Fan percentage is routed only to fans. Failed domains report diagnostics and do not prevent the remaining domains from running.

Presence entities are separate from activation triggers. Presence ON never activates an idle controller. Any configured presence ON holds an existing active session when its timer expires. The last explicit presence OFF restarts the full effective delay; unknown and unavailable events do not count as vacancy. Disable, override, constraints, interlocks and manual control retain their existing priority over the hold. Presence state is exposed separately in diagnostics.

Manual takeover records `manual_on`, `manual_off` or `manual_attribute_change`. With manual protection enabled, triggers cannot rearm the same room session while triggers or presence remain active. Once both clear, the manual block is released without a light service; a fresh activation trigger can start the next session. Manual ON/adjustment protection disabled preserves timer reset behavior. Manual OFF protection disabled allows legacy rearming; the two protections operate independently of the general blocking option.

An explicit activity-exit `restore` strategy differs from temporary attribute restoration: it returns controller outputs to their captured pre-activation ON/OFF state and readable light brightness, color and effect. This strategy runs on automatic exit and is skipped after manual takeover. Native lifecycle sequences run only when their hook selects Custom. Stored sequences remain available when a hook switches back to ON, OFF, Ignore or Restore, and cannot override the selected behavior. Delayed/waiting actions are canceled on manual takeover, reconciliation or unload; sequence errors appear in controller diagnostics.

The canonical automatic OFF policy runs when an active session ends in IDLE. Priority takeovers (override, constraint, interlock/manual blocking) keep the legacy ON/OFF behavior; explicit advanced entry hooks can define their own policy. Separate manual ON/adjustment and OFF protection switches default to enabled.

Output metadata changes such as friendly name or battery reports do not count as manual operation. Meaningful light brightness, color or effect changes and fan percentage, speed, direction or oscillation changes do. EC action contexts are recognized across all loaded EC entries. A protected manually switched-on idle output is held for the current room session without applying controller brightness; a fresh trigger may start the next session once triggers and presence have cleared.

Lifecycle diagnostics expose action timestamp, generation of the owned output snapshot, selected activity-exit strategy, and whether full restoration was skipped because of manual takeover.
